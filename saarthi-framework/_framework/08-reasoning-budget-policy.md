# Reasoning Budget Policy

Spend heavy reasoning where it has highest impact:

- requirement ambiguity
- architecture decisions
- security risks
- compliance/audit design
- complex debugging
- performance trade-offs
- concurrency/distributed concerns
- final critical review
- production incident analysis

Avoid heavy reasoning for:

- boilerplate code
- repetitive test scaffolding
- formatting
- simple refactors
- copy changes
- obvious one-file fixes
- low-risk mechanical transformations

Principle:

```text
Compress reasoning effort, not engineering discipline.
```
